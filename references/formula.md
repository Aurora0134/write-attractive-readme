# 骨架公式——hero 逐行解剖 + 章节目录

来源：alchaincyf（花叔）10 个高 star 仓库 README 实测（样本清单、star 数、许可核对与复算命令见 `corpus.md`；10 仓 LICENSE 均为 MIT）。本文件引用其中成句只为评论与说明，引用处均已标注来源仓库。百分比 = 该装置在 10 个 canonical 样本中的命中率。

## 一、Hero 逐行解剖（100% 命中，顺序不要打乱）

以 `nuwa-skill`（33k★）/ `huashu-excel` 的真实行序为基准：

| # | 行 | 命中率 | 写法要求 |
|---|---|---|---|
| 1 | `<div align="center">` | 10/10 | 包住整个 hero；**必须数清 `<div>` / `</div>` 配对**，不配对会把后文吞进居中块 |
| 2 | （可选）多语言切换行 | 2/10 | 形如 `<sub>🌐 <b>中文</b> · <a href="README.en.md">English</a></sub>`（该行原样取自 huashu-design），放在 `<div>` 之前 |
| 3 | `# 项目名` | 10/10 | 名字里可以带后缀（`女娲.skill`）或 emoji；不要带 tagline |
| 4 | （可选）hero GIF + 出处 | 7/10 | `<sub>动画由 <另一个自己的项目> 制作</sub>`——他每条都留真实出处，构成生态互证 |
| 5 | `> *「一句钩子」*` | 8/10 | ≤ 40 字，断言或反常识。三类都成立：口号式「打字。回车。一份能交付的设计。」（huashu-design）／反问式「你想蒸馏的下一个员工，何必是同事」（nuwa-skill）／引用 persona 原话「社会就是一个大筛子，用学历筛孩子，用房子筛父母」（zhangxuefeng-skill）。**不许写功能描述** |
| 6 | badge 行 3-6 枚 | 10/10 | 语义固定：`License-MIT-yellow` 放第一，协议/标准绿，`skills.sh-Compatible` 蓝，`Multi-Runtime-blueviolet`，项目专属用自定义 hex（如 huashu-excel 的 `Deps-仅 openpyxl-c2410c`）。**URL-encode 过的 badge 先 curl 状态码再贴**（未编码的 `file://` 会 400） |
| 7 | `**一句话价值主张**` | 9/10 | 独立成行、整行加粗、只讲一件事 |
| 8 | `<sub>兼容说明</sub>` | 7/10 | 「基于开放的 X 协议，可在 A、B、C…50+ runtime 中运行」（nuwa-skill 的写法） |
| 9 | 问题陈述段 3-6 行 | 9/10 | 第二人称 + 一个具体数字 + 一句「这个 X 存在的全部理由」。样板见 huashu-excel：先抛反问「"这个数你怎么算的？"——每个交过数字的人都被这么问过」，再给量化事故「比真值高 161%，零报错、零 NaN、零警告」 |
| 10 | 安装命令代码块 | 8/10 | ```npx skills add owner/repo``` 一行；紧跟「跨 agent 通用——A、B、C 都能装」 |
| 11 | 导航锚点行 | 8/10 | 形如 `[看效果](#效果示例) · [安装](#安装) · [工作原理](#工作原理)`（nuwa-skill 的写法），3-5 个，全是页内锚点 |
| 12 | （可选）Star History 图 | 2/10 | **0 star 仓库禁止放**，空图比没有图更劝退 |
| 13 | `</div>` + 空行 + `---` | 10/10 | hero 与正文的分界 |

30 秒判据：读者读完 hero 能不能说出「它是什么 + 给谁用 + 凭什么信」。答不出第三点就是重写。

## 二、正文章节目录

按此顺序排；**没有真实素材支撑的节直接删掉，不要留空壳**（宁短勿假）。

| 序 | 节名 | 命中 | 这节回答什么 | 内部装置 |
|---|---|---|---|---|
| 1 | 效果示例 / 看效果 | 8/10，且 7/8 排在安装前 | 「你说的是真的吗」 | 真跑通的输出原样贴进代码块（zhangxuefeng-skill 贴 4 段完整问答；huashu-chrome 贴 `[e7] 已点击 / 效果：expanded false → true`） |
| 2 | 装上就能用 | 10/10 | 「30 秒内我怎么开始」 | 三种安装法（一行命令 / 手动 / 当参考资料）+ 各 runtime 落盘路径表 + 「装完先自检」警告 + 唤起话术代码块 |
| 3 | 能做什么 | 4/10 | 「边界有多大」 | 表：能力 \| 交付物 \| 典型耗时。耗时必须是区间数字，不写「很快」 |
| 4 | Demo 画廊 / Showcase | 3/10 | 「最好的一行长什么样」 | 每个能力一张 GIF + 2 行说明；有 live demo 站的给站 |
| 5 | 核心机制 | 3/10 显式命中 | 「为什么它做得出来」 | 硬规则表格化：`品牌资产协议` 5 步表（huashu-design）、`五条核心原则` 编号表 01-05（darwin-skill）、`反例黑名单 8 条`（darwin-skill） |
| 6 | 和 X 的关系 | 5/10 | 「跟已有的东西差在哪」 | 定位对比表 + 一句公道话 + 收尾对句（`Claude Design 是更好的图形工具，huashu-design 是让图形工具这层消失`——huashu-design） |
| 7 | 安全与数据流 | 3/10 | 「我的数据去哪了」 | 「100% 本地、零网络零 key」这类可 grep 的断言（huashu-design）+ 指向 SECURITY.md |
| 8 | Limitations / 诚实边界 | 2/10 显式，10/10 有 inline 负面结论 | 「什么时候别用」 | 3 条加粗负面 + 一句自贬定位（`这是一个 80 分的 skill，不是 100 分的产品`——huashu-design） |
| 9 | 仓库结构 | 8/10 | 「代码在哪」 | ```tree``` 代码块，每个文件后面一句它管什么 |
| 10 | 起源 / 背后的故事 | 3/10 | 「为什么会有这东西」 | 第一人称、有时间、承认灵感来源与 borrowed 的部分（nuwa-skill「背后的故事」、huashu-design「起源」） |
| 11 | License | 9/10 | 「我能干什么」 | 一句人话（`MIT — 随便用，随便改，随便造`——nuwa-skill）；改过协议就写清生效日期与旧条款作废（huashu-design 2026-05-14 的写法） |
| 12 | 关于作者 | 9/10 | —— | **花叔的资产，不是骨架的必需件**。本仓库作者偏好见 SKILL.md 红线：默认不写平台表 / 账号 / 二维码，改写「反馈与贡献」 |
| 13 | 居中收尾对句 | 5/10 | 回扣钩子 | `<div align="center">` + 两行 `**加粗**` + `<br>` + 钩子原句重述（nuwa-skill 结尾的写法） |
| 14 | ## English | 2/10 | 国际读者 | 6-10 行摘要，不是全文翻译 |

## 三、三档变体（选一行当基准，别混）

**A. 能力型 skill（nuwa-skill / huashu-design / huashu-excel / huashu-md-html / huashu-chrome）**
按上表全量。字数最多、机制最重，核心机制节是主角。

**B. 生成物型（zhangxuefeng / steve-jobs / x-mentor 等女娲产物）**
共用同一套模板，节名固定：`效果示例（4 段问答）→ 安装 → 蒸馏了什么 → 调研来源 → 这个 Skill 是怎么造出来的 → 仓库结构 → 更多 .skill → 许可证 → 关于作者`。特征是**把输入素材的量化清单当卖点**（`基于5本著作、15+篇权威媒体深度采访、30+条一手语录、11个关键决策记录`——zhangxuefeng-skill）和**把来源列成表**（一手 / 二手分开）。适合任何「从资料里提炼出产物」的仓库。

**C. 产品/App 型（fanbox）**
双语标题（`## What it does · 能做什么`），面向国际读者，重心在截图 + 下载 + 快捷键表。**只在项目真的要给非中文用户时用**；纯中文项目套这档会变成两头不靠。

## 四、离群形态（明确不要照抄）

`img2046`（普通工具站 README：无 hero、无 badge、有「强大的」）、`huashu-skills`（目录索引型：16 张表、零 hero）、`hermes-agent-orange-book`（书/文档型：语言切换行 + 目录）、`huashu-report`（极简 89 行，无 hero）。校验器给这 4 个判 2-4 FAIL，给 A/B 档判 0-1 FAIL——差异是形态不同，不是他写得不好。**用户的「花叔风格」= A/B 档。**
